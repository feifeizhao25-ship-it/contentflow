# 分发侠 ContentFlow v3.0 产品改善与开发文档（生产级）

## 0. 目标与边界

### 0.1 产品目标
*   **价值交付**：3分钟内生成可发布“内容包”；10分钟内完成“生成→排期→发布任务创建”
*   **增长飞轮**：发布→复盘→复刻→批量排期，形成高留存
*   **商业化**：通过多平台适配、封面/视频生产、批量排期、稳定发布、团队协作、Developer API 拉高 ARPU
*   **生产可用**：可观测、可回滚、可控成本、可审计、可合规

### 0.2 不做什么
*   不承诺 100% “真实平台一键发”覆盖所有平台（先以可插拔适配器推进）
*   不把社区/成就做成主导导航（作为增长插件存在）

---

## 1. 核心改进领域

### 1.1 合规与风控
*   **平台合规**：集成敏感词库，对 AI 输出做安全过滤。
*   **版权标识**：素材库需记录来源与商用授权标识。
*   **账号安全**：Token 加密存储（AES-256），支持定期失效提醒。

### 1.2 成本与额度
*   **UsageMeter**：记录每次请求耗费的 Token、图片及视频生成数量。
*   **CostLedger**：后端记录估算成本，支持毛利分析。
*   **Cache**：针对相同 Prompt 实现结果缓存，降低重复成本。

### 1.3 可观测性
*   **Tracing**：引入全链路 `trace_id`。
*   **SLO**：监控成功率（生成/发布）与 P95 延迟。

---

## 2. 功能系统：内容包 (Content Pack) 模式

### 2.1 引擎闭环
1.  **生成**：一次请求产出 10 个标题、1 套正文脚本。
2.  **适配**：根据各平台（小红书/抖音/公众号）自动调整格式。
3.  **封面**：调用 AI 生成多版封面图，支持尺寸一键转换。

### 2.2 开发者平台 (Developer API)
*   **API Keys**：提供带 Scope 的密钥管理。
*   **Webhooks**：支持 `content.generated`, `publish.task.success` 等事件订阅。
*   **Playground**：在线调试 API。

---

## 3. 技术实现要点

### 3.1 数据库增强
*   `UsageMeter`: 租户级资源消耗统计。
*   `ApiKey`: 散列存储的外部访问密钥。
*   `AuditLog`: 关键操作审计追踪。

### 3.2 权限模型
*   **RBAC**: 区分 Owner, Admin, Editor, Reviewer。
*   **Isolation**: 强制 `tenant_id` 物理/逻辑隔离。

---

## 4. 研发路线图

*   **Sprint 1**: 成本统计地基 + 内容包引擎。
*   **Sprint 2**: 开发者 API 展示 + 密钥管理。
*   **Sprint 3**: 复盘飞轮 + Webhook 实现。
