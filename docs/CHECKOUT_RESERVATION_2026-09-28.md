# 首次下单并发与失败保护

2026-09-28。首次下单先通过数据库唯一键保存待支付订单，再调用支付适配器。只有成功插入订单的请求可联系平台；相同租户与幂等键的竞争请求读取胜出订单，参数不同返回冲突。支付链接尚未保存时明确提示正在生成或需要核对，禁止自动另开支付订单。

数据库插入失败不会联系平台。平台失败或链接写入失败保留已提交的订单，便于签名回调按原订单号匹配；不以删除订单方式掩盖未知支付状态。保存链接只更新链接字段，不能覆盖同时发生的付款或关闭状态。

## 验证

- API 38 组、225 项测试通过；Nest 构建和修改生产文件 ESLint 通过。
- 新增测试覆盖插入失败、平台失败、链接保存失败、唯一键冲突重放和保存期间订单已支付。
- 本地隔离 PostgreSQL 17 共 15 个场景通过，包括五请求同时创建同一订单、不同参数复用幂等键被拒绝，以及此前的续费和退款并发场景。
- 支付平台由测试替身模拟；数据库竞争使用真实本地 PostgreSQL，测试对公账号为固定虚构字符串，不发生真实转账。日志见 evidence/2026-09-28-checkout-reservation/。

## 剩余限制

结果未知的订单保留待支付状态，当前要求核对，不自动再次调用平台。尚需实现平台订单查询、失效链接恢复、平台关单和本地关单一致性、自动对账与多订单退款账本。用户若改用新幂等键仍可另开订单，尚无跨购买意图去重保证。本轮未进行真实商户支付或生产部署。沿用此前 payment_url 数据库迁移，未新增迁移。
