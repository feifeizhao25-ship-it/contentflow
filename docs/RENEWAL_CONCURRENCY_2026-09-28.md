# 跨订单续费和退款并发修复

2026-09-28：同一租户的支付和退款事务在读取并变更权益前，以参数化 SQL 锁定 Tenant 行，再读取订单最新状态。避免两个不同订单同时续费时从相同到期日计算，丢失一次续费；退款和新付款也使用同一锁，避免退款覆盖新购权益。

退款保护查询同时考虑已支付和退款申请中的更新订单，并纳入相同支付时间的另一订单，停止自动撤销权益以待核对。

## 验证结果

- API 37 组、212 项单元测试通过，Nest 构建通过，修改的生产源文件 ESLint 通过。
- 全部迁移在本地新建隔离 PostgreSQL 17 数据库 contentflow_ci 通过。
- PostgreSQL 并发脚本共 12 个场景通过，包括付款与关闭争用同一订单、不同事件付款、不同订单同时续费、退款与新付款同时发生。脚本现有 CI 入口会执行新增场景。
- 反例验证：只在临时构建产物中移除租户锁，测试发现到期日为 2030-02-15，而预期为 2030-03-15，明确检出少续费一个月。恢复产物后重新执行全部 12 个场景通过。源代码始终保留修复。
- 测试脚本清理本次创建的记录，本地测试数据库服务随后停止。日志见 evidence/2026-09-28-renewal/。

## 边界与后续

本地数据库并发通过不是生产支付验收。尚需处理重复下单支付链接恢复、多笔历史购买的退款与剩余时长结算、交易号跨订单唯一性。发现更新购买时仍保守拒绝自动完成退款，不代表退款已在商户侧完成；需要账务核对流程。尚未执行真实扣款、商户退款或生产部署。
