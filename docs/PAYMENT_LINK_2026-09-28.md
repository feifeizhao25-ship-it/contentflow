# 支付链接恢复与历史权益保护

2026-09-28。

## 修改

支付订单增加可空 payment_url 字段。首次下单把支付平台返回的链接保存到订单；同一租户、同一幂等键、同一购买参数重试时，待支付订单返回已保存链接，不再次调用支付平台。已支付、关闭或退款相关状态的订单不提供 paymentUrl。旧的在线支付订单没有保存链接时，明确返回需核对的冲突，避免无声返回不可支付的订单。

退款时只要存在其他已支付或退款申请中的购买记录，就停止直接撤销当前订阅，提示核对剩余会员时长。此前只保护较新的订单，退最新一笔续费可能清空更早购买的剩余时长。此修改是防止错误撤销的保护，不是多订单退款账本实现。

## 验证

- 38 组、220 项 API 测试通过；Nest 构建、修改的生产源码 ESLint 通过。
- 本地隔离 PostgreSQL 17 升级迁移通过；实际读写验证支付链接持久化、旧订单字段为 null、旧金额保持不变。
- 12 个 PostgreSQL 并发场景通过。
- 日志见 evidence/2026-09-28-payment-link/。本次未调用真实商户下单或退款接口。

## 部署与剩余工作

部署前在 runtime/api 执行 `npx prisma migrate deploy`，再发布已重新生成 Prisma Client 的应用；迁移 202609280001_payment_link 仅新增可空字段，旧数据不需要伪造链接。

保存链接不保证平台链接永不过期；尚未实现失效链接查询和恢复。历史缺失链接需核对支付平台状态。首次创建订单并发和平台成功但数据库写入失败的恢复仍需继续处理。多笔历史购买的逐笔时长账本、退款扣减及自动结算仍未实现，当前保守阻止自动撤销以待核对。真实商户与生产环境验收未完成。
